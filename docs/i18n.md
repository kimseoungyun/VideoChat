# 화면 언어 (한국어 / English)

- **범위**: 대화 화면 전체(서버가 그리는 HTML, 브라우저 스크립트가 띄우는 상태·오류 문구, WebSocket 오류 메시지)를 한국어와 영어로 제공합니다. 정책 페이지와 계정 페이지는 아직 한국어만 있습니다.
- **언어 결정**: 기본은 한국어이고, 헤더에서 사용자가 언어를 고를 때만 바뀝니다(`django_language` 쿠키). 브라우저의 Accept-Language는 따르지 않습니다. 한국어 우선 서비스라 예측 가능한 동작을 택했습니다(`myproj/locale.py`).
- **구현**: Django 표준 i18n을 씁니다. 템플릿은 `{% translate %}`·`{% blocktranslate %}`, 스크립트는 `JavaScriptCatalog`(`/jsi18n/`)의 `gettext`/`interpolate`를 씁니다. 서버 오류는 consumer가 소켓 쿠키의 언어로 번역합니다. 원문(msgid)은 한국어입니다.
- 매칭 언어 선택(ko/en/ja/zh)과 화면 언어는 별개입니다. 일본어·중국어 화면은 없습니다.

## 문자열을 추가하거나 바꿀 때

이 저장소의 개발 PC(Windows)에는 GNU gettext가 없어서 `makemessages`/`compilemessages` 대신 `scripts/messages.py`를 씁니다.

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt   # Babel
.venv\Scripts\python.exe scripts\messages.py missing   # 코드에 있지만 번역이 없는 문자열
# backend/locale/en/LC_MESSAGES/django.po 또는 djangojs.po에 번역 추가
.venv\Scripts\python.exe scripts\messages.py compile   # .po → .mo (커밋)
```

- 서버 테스트(`I18nTests`)가 다음을 검사합니다.
  - 번역 누락이 없는지
  - 영어 화면에 한글이 남지 않았는지(언어 이름 "한국어" 제외)
  - Accept-Language와 관계없이 기본이 한국어인지
  - WebSocket 오류가 영어로 오는지
- CI는 커밋된 `.po`로 `.mo`를 다시 만들고, 커밋된 `.mo`와 다르면 실패합니다. Babel이 컴파일 시각을 헤더에 넣어 결과가 매번 달라지는 문제가 있어, 날짜를 고정해 결과를 재현 가능하게 했습니다.
- e2e `tests/i18n.cjs`는 헤더에서 English를 고른 뒤 동의 화면과 매칭 대기 문구가 영어로 나오는지 확인합니다.
